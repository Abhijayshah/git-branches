Industry Git Branching Workflows

Learn how top engineering teams structure their branches for feature development, code reviews, and production deployments.

🌿

Feature Branch Workflow

Beginner

All feature development takes place in a dedicated branch instead of main. This keeps master clean and enables safe pull request reviews.

1
Create Branch: git checkout -b feature/auth
2
Work & Commit: git commit -m "Add auth"
3
Merge to Main: git checkout main && git merge feature/auth
🐙

GitHub Flow

Intermediate

A lightweight, branch-based workflow that supports teams and projects that deploy regularly. Anything in main is always deployable.

1
Branch off main: Descriptive name e.g. add-search-bar
2
Open Pull Request: Discuss and review code with peers
3
Deploy & Merge: Test, deploy to production, then merge
⚙️

Gitflow Workflow

Advanced

A robust framework for managing larger projects with scheduled release cycles. Uses strict branch roles: main, develop, feature/*, release/*, and hotfix/*.

1
Develop Branch: Integration branch for features
2
Release Branch: Prepare release details & final bug fixes
3
Hotfix Branch: Patch production main emergency bugs

Git Branching Interactive Challenges

Test your knowledge by completing tasks in the simulated terminal.

⭕

Challenge 1: Create & Switch Branch

Create a new branch named feature/login and switch to it using git checkout -b feature/login or git switch -c feature/login.

⭕

Challenge 2: Make Commits on Your Branch

Make a new commit on your branch using git commit -m "Add login UI".

⭕

Challenge 3: Merge Back into Main

Switch back to main branch, then merge feature/login into main.

⭕

Challenge 4: Clean Up Merged Branch

Delete the merged feature/login branch using git branch -d feature/login.
